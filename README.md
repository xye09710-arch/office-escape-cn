# 今天必须准时下班 · 剧情连贯版

下午五点，日报还剩个尾巴，老板又想起了 PPT。十八次选择，能不能把今晚还给自己？

轻量中文职场网页游戏，像素办公室、四档难度、六种结局、十四张确定解锁的成就。纯静态网页，无账号、付费接口或抽卡。

## 本地试玩

需要 Node.js 24、npm 11。

```bash
npm ci
npm run dev
```

打开终端显示的地址。每次决策自动存档，刷新后点击“继续上次”。开始新一局会替换当前进度，保留收藏。旧版局面因剧情结构不同无法直接续玩，会留档并保留已有卡牌，页面提示重新开局。

## 这次的剧情规则

每局固定十八个剧情节点，四阶段分别为四、五、五、四次决策。**节点固定，具体情境不固定**：同一节点可能是小陈来回帮、没人有空，或你已经把回帮用在代听会议上。当前有五十六种情境，每局只会遇到其中十八种，不按事件数量填满一局。

- 帮过哪个人、接过什么活、哪个文件确认收到，都记录具体事实及来源。五条交叉故事围绕日报、临时稿、会议、互助和离场展开。
- 事件依据节点、真实前置条件和任务状态唯一匹配。没有 `storyKey`，没有事件权重抽取；相同难度与选择得到相同故事。
- 任务账本记录余量、来源、追问节点、接手人和改期约定。接活新增负担；完成才增加完成度；延期或委托不会假装任务已经做完。接回的任务重新处理，仍保留来龙去脉。
- 日报初始完成四份、还剩八份标准工作量，显示约三分之一完成。新增任务可能使总完成度降低。工作量单位表示正常速度下的估算分钟，不是点一下就到账的奖励分。
- 普通协商、休息、静音、借模板、冒险用缓存都可以选择。缓存会留下校验待办；未参与的会议要补范围确认；改期是否成功取决于今晚是否要用、之前作过什么承诺。
- 每次选择显示具体反馈和实际状态变化，任务去向与历史可展开查看。反馈与事实、账本一起存档。
- 保留当前时间、工作完成度、老板怀疑值、同事关系、疲劳值。怀疑值不是无条件返工税：有回执可澄清漏看，数据真的没核则仍要处理。

## 难度、排名与结局

难度改变 PPT 和新增数据的实际量、会议时长、干活速度与同事的初始收尾时间，不统一惩罚休息和正常回复。疲劳高时实际工作会慢一些，休息可以恢复。

四位同事各有工作节奏。帮他们能减少其工作负担，请他们代做会增加其负担。时间线保证他们不可能在后续仍到场帮忙、排名中却早已离开。约好一起走后，还得选等待并计入时间，双方才在同一分钟下班。

六种结局保留为：准点下班、组队撤离、晚了一点、门口被叫回、尾款是加班、工位续费。结算依据实际任务、离场经历和时间，具体规则如下：

1. 疲劳至少六十五且预计收尾已到十八点半，额外复核后进入“工位续费”。
2. 实际发生过因未清任务或交接而返回工位，进入“门口被叫回”。
3. 最后选择留下补欠项且实际离开晚于十八点，进入“尾款是加班”。补完的每项列在结算清单中。
4. 自己交接妥当、无未解决事项，且选择与约好的搭子同行，进入“组队撤离”。等待也计入时间。
5. 其余在十八点前或整点离开为“准点下班”，之后为“晚了一点”。

所有结算保留实际任务去向和收尾明细；结局卡牌按最终事实解锁，稀有度只表示达成难度。已有收藏沿用原卡牌编号；“聊天记录战神”按至少两次实际留存或核实交付证据判定。

## 测试

```bash
npm test          # 剧情、任务、数值、六结局、卡牌和存档
npm run test:e2e  # 桌面、手机、窄屏手机的真实浏览器通关
npm run build    # 生产构建到 dist
npm run check    # 全部验收
```

浏览器测试优先使用系统 `/usr/bin/chromium`；其他系统可运行 `npx playwright install chromium`，或用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定路径。受限环境可用 `npm ci --cache /workspace/.npm-cache`。

自动化模拟一万局，检查五十六种情境实际可达、每个节点唯一匹配、任务不丢失和状态连续性；主要分支另有固定路径测试，不用随机抽到算通过。十四张卡均有固定见证路径。桌面、390 像素手机和320 像素窄屏测试覆盖完整通关、续玩、反馈、收藏迁移、分享，以及提前下班和明显加班两条路线。手机为 Chromium 触屏模拟，未宣称所有真机浏览器均已实测。

可复现的中文逐题路线见 [剧情验收路线](docs/story-routes.md)。

## 技术结构

| 文件                           | 用途                                     |
| ------------------------------ | ---------------------------------------- |
| `src/events.js`                | 中文情境、选项、具体条件和后续关系       |
| `src/engine.js`                | 节点匹配、任务转移、事实来源与连续性检查 |
| `src/tasks.js`                 | 任务账本、完成度、延期、委托和接回       |
| `src/rules.js`                 | 难度、同事时间线、六结局和收尾明细       |
| `src/state.js`                 | 初始状态、阶段和存档版本                 |
| `src/achievements.js`          | 十四张卡牌的确定条件                     |
| `src/storage.js`               | 历史重放、旧档留存、收藏迁移             |
| `src/main.js`、`src/style.css` | 保留的像素界面，新增反馈与账本           |
| `tests/fixtures/paths.json`    | 六结局、主要分支与十四张卡的固定见证路径 |

## Netlify 部署

连接本仓库创建新站点，使用 `netlify.toml`：Node.js 24、构建命令 `npm run build`、发布目录 `dist`。也可构建后将 `dist` 上传至新站点，不需要服务端、密钥或付费 API。使用 HTTPS 可支持复制战绩；剪贴板不可用时显示手动复制文本。

本任务不自动创建或覆盖任何既有 Netlify 站点。
